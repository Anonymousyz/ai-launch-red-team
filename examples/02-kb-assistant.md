# 示例 02:内部知识库问答助手(一条否决触发,授权与日志说不清)

## 输入方案

> 给全公司做一个知识库问答助手:把近三年的客服工单、内部 wiki 和部门共享盘文档整理成向量库,检索后调某海外大模型 API 生成答案。只读不写,风险很低,先在行政和 HR 试用,反馈好就推全员。预算走部门经费,量不大。

## 追问清单(带去评审会)

1. 共享盘里的薪酬表、合同、身份证复印件会不会被向量化?谁做过入库前的密级筛查?
2. 这家海外模型服务商在公司的供应商或安全批准名单上吗?数据出境有没有合规结论?
3. "只读"的边界:HR 把错误答案当政策执行造成损失,算谁的?答案要不要强制附来源引用?
4. 有没有 50 到 100 条带标准答案的测试问题?"反馈好"的通过线是多少?
5. 员工提问和检索命中会不会留日志?查到敏感内容泄露时能不能定位到人?
6. 全员推广后的月调用量和费用测算是多少?封顶在哪?

## 红队建议

否决 2 不解决,其他都免谈:要么换公司批准的模型部署形态(私有化或已批准的境内服务),要么在入库和提示两层做脱敏并拿到安全与合规的书面批准。同时把"反馈好"换成可核验的通过线(测试问题集 + 命中率 + 来源引用率),入库范围从"三类全量"收缩为"逐类批准的白名单"。试用阶段的设计是对的,保留。
