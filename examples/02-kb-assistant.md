# 示例 02：内部知识库问答助手（一条否决触发，授权与日志尚不清楚）

## 输入方案

> 面向全公司建设知识库问答助手：将近三年的客服工单、内部 wiki 和部门共享盘文档整理为向量库，再调用海外大模型 API 生成答案。系统只读不写，风险较低；先在行政和 HR 部门试用，反馈好再向全员推广。预算从部门经费中支付，预计用量不大。

## 追问清单（带去评审会）

1. 共享盘中的薪酬表、合同和身份证复印件会不会进入向量库？谁完成入库前的密级筛查？
2. 该海外模型服务商是否在公司的供应商或安全批准名单中？数据出境是否已有合规结论？
3. “只读”的边界是什么？HR 若将错误答案当作政策执行，责任如何划分？答案是否必须附上来源引用？
4. 是否有 50 至 100 条带标准答案的测试问题？“反馈好”的通过线是多少？
5. 员工提问和检索命中是否留痕？出现敏感内容泄露时，能否定位到相关记录？
6. 全员推广后的月调用量和费用测算是多少？费用达到什么阈值时限流或停用？

## 红队建议

先处理第 2 条否决：确认可用的模型部署方式，或者在入库和提示两层完成脱敏，并取得安全与合规的书面批准。随后把“反馈好”改为可检查的通过线，例如测试问题集、命中率和来源引用率；入库范围也应从“三类全量”收缩为逐类批准的白名单。行政和 HR 试用可以保留，但应在这些条件明确后开始。
